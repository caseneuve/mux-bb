# Code Review: mux-bb initial repo

## Summary

Clean, well-structured Babashka library with a strong FCIS architecture. The pure/impure separation is genuinely good. However, there are several bugs in pure functions (nil-safety, invalid tmux identifiers from slashes in project names, empty-string pass-through in arg builders), missing test coverage for important edge cases, and a protocol contract that could be made more robust. The test suite is solid for the happy path but doesn't stress the boundaries enough for a shared library that two repos will depend on.

- Tests: PASS (20 tests, 82 assertions, 0 failures)
- Linter (clj-kondo): PASS (0 warnings, 0 errors)
- clojure-lsp: SKIP (no JVM on host — expected for bb project)

## Findings

### Critical

- [ ] **src/mux/cmux.clj:14** `escape-send-text` throws NPE on nil input. `(str/replace nil ...)` fails. The function is called in `:send!` where user text flows in. Either guard with `(str text)` or document non-nil precondition — but since `:send!` already does `(str text "\n")`, the nil arrives pre-concatenated as `"\n"` which is safe. However, `build-cmux-args` calls `escape-send-text` on `(:text params)` directly, and a caller could pass `{:text nil}`. Should be `(escape-send-text (or (:text params) ""))` or guard in `escape-send-text` itself.

- [ ] **src/mux/tmux.clj:14-19** `derive-session-info` produces invalid tmux identifiers when `project` contains `/` (e.g. `"my/project"` → session `"my/project-c6c1d9"`, sock path `"/tmp/claude-my/project-c6c1d9.sock"`). Tmux session names cannot contain `.` or `:`, and socket paths with `/` in the filename portion create nonexistent parent dirs. Either sanitize the project name (replace disallowed chars) or document the constraint. Since this is a shared library, sanitization is safer — consumers will pass raw directory/repo names.

- [ ] **src/mux/cmux.clj:28** `build-cmux-args :capture` with nil `:lines` produces `["capture-pane" "--workspace" "ws" "--scrollback" "--lines" ""]` — an empty string arg that will likely cause cmux CLI to error or misbehave. The `scrollback-lines` default (1000) is used in `make-backend`, but `build-cmux-args` is a public pure function that any caller can invoke directly with bad params. Should validate or default `:lines`.

### Important

- [ ] **src/mux/cmux.clj:24-35** `build-cmux-args :send` passes empty-string workspace through: `{:workspace ""}` produces `["send" "--workspace" "" "--" ...]`. The `cond->` guard `(:workspace params)` is truthy for `""`. Same issue affects `:capture`, `:notify`, `:set-description`, `:set-color`. Use `(seq (:workspace params))` consistently, matching how `detect-mux` uses `seq` for empty-string checks.

- [ ] **src/mux/tmux.clj:60-67** `make-backend` `:new-window!` doesn't track created windows. Unlike cmux's backend which has a `workspaces` atom and `require-workspace!`, tmux's `:send!` and `:capture!` will happily attempt operations on any name string — even windows that don't exist. If a caller typos a window name, tmux silently fails or errors late. Consider: (a) adding a `windows` atom like cmux does, or (b) documenting the asymmetry clearly in the protocol docstring. For a shared library, consistency matters.

- [ ] **src/mux/tmux.clj:67-70** `make-backend` `:list!` uses `tmux?` (nil on failure) then `some-> ... str/split-lines`. If the tmux session doesn't exist yet, this silently returns nil, not `[]`. The protocol contract says `(fn [] → [name ...])` — nil breaks callers doing `(count ((:list! be)))` or `(map ...)`. Should return `(or ... [])`.

- [ ] **src/mux/cmux.clj:93-121** `make-backend` `:new-window!` is a 25-line function with nested try/catch, retry logic, and Thread/sleep. This is the most complex function in the codebase and has zero test coverage beyond "the fn exists". The retry-and-fallback logic (create fails → try find-by-name → throw) is business-critical. Consider extracting the retry logic into a testable helper, or at minimum, add structural tests that mock `cmux!` to verify the fallback paths.

- [ ] **test/unit/cmux_test.clj** No tests for `build-cmux-args` with missing/nil required params. The happy paths are well covered, but the edge cases I found above (nil `:text`, nil `:lines`, empty-string `:workspace`) are the ones that will bite consumers. A shared library needs adversarial tests for its public pure functions.

- [ ] **src/mux/protocol.clj:35-40** `make-backend` uses `require`/`resolve` for lazy loading, which is good. But the `case` gives an opaque error on unknown backend types: `No matching clause: :zellij`. A more helpful error: `(throw (ex-info (str "Unknown mux backend: " backend-type) {:type :unknown-backend :backend backend-type}))`.

### Minor

- [ ] **src/mux/cmux.clj:52-64** `parse-workspaces` regex `#"^([* ]?)\s*(workspace:\S+)\s+(.+)"` — the `[* ]?` capture group matches either `*`, a space, or nothing. When `sh` trims the first line, the leading `*` or space may be gone. Current tests cover this, which is good. But note: if cmux ever outputs a workspace line like `  workspace:1` with no name after it, the regex requires `.+` so it won't match — a workspace with an empty name is silently dropped. This is probably fine but worth a comment.

- [ ] **src/mux/cmux.clj:155-174** `:notify!`, `:set-description!`, `:set-color!` all swallow exceptions with `(try ... (catch Exception _ nil))`. This makes debugging impossible when cmux CLI changes or a workspace ID becomes stale. Consider at minimum logging to stderr, or returning `nil` vs `false` to distinguish "succeeded" from "failed silently".

- [ ] **src/mux/shell.clj:8-14** `sh` builds the error message with `(pr-str args)` which works but includes the lazy-seq wrapper. Minor readability issue in error messages: `Command failed (exit 1): ("false")` — the parens suggest a list, not a command. Consider `(str/join " " args)` for the display string.

- [ ] **test/e2e/cases.edn:35** `:send-and-capture` case wraps the run command in double vector `[["bb" ...]]`. This appears to be an end2edn convention for sequential commands, but there's only one command. Either this is unnecessary nesting, or it's intentional for the framework — clarify with a comment.

- [ ] **bb.edn** `test:ci` task checks `(System/getenv "CI")` but there's no CI config in the repo (no `.github/workflows/`, no `.gitlab-ci.yml`). If CI is planned, this is fine. If not, it's dead code.

- [ ] **README.md:18-22** The "Detect backend" example calls `(into {} (System/getenv))` which works in bb but is unusual — `System/getenv` already returns a map-like object. Document that `detect-mux` expects a plain Clojure map (not a Java map), or make `detect-mux` work with both via `(get env key)` which already works for both. Actually, `get` works on Java maps too, so this is fine — but the README example adds unnecessary conversion.

## Test Coverage Assessment

**Good:**
- All pure functions (`escape-send-text`, `build-cmux-args`, `parse-workspaces`, `detect-mux`, `derive-session-info`, `build-target`, `md5-hex`, `md5-short`, `sh`, `sh?`) have tests
- Backend structure tests verify protocol keys exist
- Error behavior tested for unregistered windows in cmux
- E2E covers the tmux create → send → capture lifecycle

**Gaps:**
- No edge-case tests for nil/empty params in `build-cmux-args` (Critical bug found via nil `:text`, nil `:lines`, empty-string `:workspace`)
- No test for `escape-send-text` with nil input
- No test for `derive-session-info` with special characters (slashes, dots, colons) — these produce invalid tmux identifiers
- No test that tmux `list!` returns `[]` (not nil) when session doesn't exist
- No adversarial tests for `parse-workspaces` (partial lines, no name after ID)
- `make-backend` imperative logic in cmux (the retry/fallback in `:new-window!`) has zero behavioral coverage — only structural "fn? exists" checks

**Risk level:** Medium-high for a shared library. The pure function coverage looks comprehensive at first glance but misses the boundary inputs that are most likely to occur in production (nil, empty strings, special characters in project names).

## Security Assessment

No security issues identified. The library:
- Doesn't handle user input from untrusted sources
- Shell commands use `babashka.process/sh` with arg vectors (not string concatenation), preventing injection
- E2E tests run in podman containers
- No filesystem writes, no network calls, no secrets handling

One note: `signal-cmd` in cmux returns a shell command string that callers will presumably pass to a shell. If `signal-name` contains shell metacharacters, that's an injection vector at the caller's level. Not this library's bug, but worth a docstring note.

## Positive Observations

- **FCIS architecture is genuinely clean.** The pure/impure boundary is sharp — `build-cmux-args`, `parse-workspaces`, `derive-session-info` are all truly pure and independently testable. This is well done.
- **Protocol-map-as-interface pattern works well** for Babashka's constraints (no deftype/defrecord). The map keys are consistent between backends.
- **Test organization is solid.** Unit tests mirror source structure, runner is simple, E2E uses declarative EDN format.
- **bb.edn tasks are well-designed.** The podman isolation for tests, the host shortcut for iteration, the CI guard — all show thoughtful workflow design.
- **Documentation is above average.** AGENTS.md, README.md, and .claude/rules together give a complete picture.
- **Code is concise and readable.** Functions are short, naming is consistent (! for imperative, ? for predicates), threading macros are used where they help.
